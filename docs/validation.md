- 40 个常用拼音与前文消歧样例：首选 40/40。
- 12 个简拼、混拼、纠错、分音样例：首选 12/12，包括 `nh`、`srf`、`shurf`、`shurfa`、`diannoa`、`xi'an`。
- 后文比较：前文相同为“他的”，`yao` 后接“可以缓解症状。”时首选“药”；后接“部受伤了。”时首选“腰”。
- 快速输入 `s → sh → shu → shur → shuru → shuruf → shurufa`：最终完整候选为“输入法”，旧任务不覆盖新请求。
- 学习记录创建、持久化、删除、撤销、暂停/恢复；测试记录清理，Rime 测试关闭学习，不污染个人词表。
- 真实 Rime DLL 加载实际 Lua：逐键输入、Tab 更新、空格上屏；一两个字分次上屏的前文恢复；网页前文切换不影响 Rime 会话。
- Rime 文档快照协议：前文变化、输入框切换、过期快照被忽略。此项使用合成快照。

- Windows 文档辅助程序编译零警告/错误、常驻运行；实际能报告不支持的控件及密码控件，密码状态不包含文本。

## 延迟

这是短时、本机、多轮调试后的样本，不是稳定的 SLA。时间包含客户端往返。

| 测量项 | 结果 |

| 提供前文字符数 | 首批候选数 | 完整单字消歧耗时 | 同查询缓存中位数 |

超过 256 字的前文截取最近 256 字；Unicode 截取也测试了辅助平面汉字。缓存是完整 token 前缀的计算结果复用，不是增量 KV 缓存。

## 结果的边界

52 个样例是人工构造的开发回归集，部分曾用于发现并修复问题；不能把 52/52 当成真实准确率。没有独立语料评测，也没有对常规输入法做公平对照。未完成 Word、VS Code、各浏览器等应用的真实光标读取兼容矩阵；合成快照通过不证明这些应用都能被 UI Automation 读取。

Rime 当前只能在按键、Tab 或空格时更新后台完整结果，没有空闲自动刷新。有限搜索、两个后文 token、纠错和个性化权重都有局限；仍可能出现错误或不自然候选。长词完整搜索通常需要几百毫秒；用户提前按空格可能等待剩余搜索。

# Rime 完整候选修复（2026-10-09）

Rime 同步 Lua 接口目前无法在空闲时接收后台结果。因此系统前端改为等待覆盖整串输入的候选，而非停留在首 token；无需按 Tab。新的 usable 等待点在完整候选出现时释放，不等待额外后文比较。完整拼音优先搜索严格读音分支，简拼保留原排序规则。
